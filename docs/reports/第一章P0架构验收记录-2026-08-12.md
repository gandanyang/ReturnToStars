## 二、验收通过的关键点（制作人确认）

1. **不污染旧存档**：`chapter?: number`（可选字段）而非强制迁移 `chapter: 0`。
   - 老玩家存档安全；不增加 SAVE_VERSION 压力；后续字段扩展空间大。
2. **章节切换点锁死**：观星夜最终存档前 `setChapter(CHAPTER_1)`。
   - 时序：观星夜 → 保存 → chapter=1 → 第一章内容开放。
   - 消除风险："玩家看到第一章内容，但剧情状态还停留第0章"。
3. **EventCondition 作为扩展层**：`triggerOnceIf(id, cond, fn)` 不改 `EventManager` 核心。
   - 优于 `triggerOnce(id, { condition })`；出问题可快速定位。

## 三、EventCondition v1 冻结（制作人拍板）

```ts
EventCondition {
  chapter?  // 最低章节
  quest?    // 主线任务状态
  restore?  // 世界恢复点
}
```

- **只允许 chapter / quest / restore 三个字段**，禁止继续扩展（npc / item / time / weather / relationship / money 一律不加）。
- 理由：条件字段已接近"任务系统"，无限扩展会退化成半吊子 RPG 框架；第一章由这三个字段足以支撑。
- 缺语义时用**多个条件事件组合**，而非扩展字段。
- 如需新增字段：先写方案交制作人评审，不得自行扩展。
- 已落实到 `src/systems/EventManager.ts` 注释（冻结声明）。
