### getRevivalLevel 决策（兼容性）

任务书要求"marketSquare 计入后 Lv2 条件仍正确"。**决策：getRevivalLevel() 不变**（三建设点语义），原因：
- 木匠回归条件 = `getRevivalLevel() >= 1 && hasTriggered('carpenter_returned')`（NPCSystem.ts:427）——改动会波及既有回归逻辑
- marketSquare 是第一章内容（村长来访解锁），而三建设点是第0章/早期内容；把第一章内容塞进 Lv 判定会让旧档读档后复兴度突变
- "兼容" = 不破坏，市场恢复作为独立反馈呈现（归星记录 + 地图/NPC 变化已足够可感知）

## 四、施工过程中的决策与问题记录

1. **并行编辑冲突（FarmRestore.ts）**：并行 Agent 与本会话几乎同时修改 `RESTORE_KEYS`/`RESTORE_PROJECTS`，产生重复配置行与注释叠层 → 立即读取最新内容修复合并，无逻辑残留（教训：多 Agent 并行改同一文件时先读再写，写入失败即重读）。
2. **探针 M3 首次运行失败（7/8）**：原版 M3 读 StoryDialogue 文本，但首次进镇剧情（TOWN_INTRO 等）为延迟 auto 事件，晚于 dismissDialogue 弹出 → 按 E 命中对话而非集市。并行 Agent 已同步将 M3 改为"重新进 town 种子档 + 读 `dialogueText`（offerQuickBuy cost=null 走 `showDialogueText` 的路径）"，重跑 8/8。
3. **触发时序纪律**：`tryMarketSquareComplete` 中 `markRestored` → 换视觉 → `save()`（save 在状态标记后，读档保持恢复态）；非 `triggerOnce` 路径，无"先 fn 后标记"坑。
4. **零新素材**：荒废/修复两态全部 Graphics 程序绘制（复用 forestRoad/oldHouse 范式），无新图片资产。
