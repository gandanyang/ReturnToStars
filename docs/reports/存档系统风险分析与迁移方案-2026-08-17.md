> 触发：制作人要求分析——①存档污染风险 ②版本迁移支持 ③改进方案；不重写全部代码。

## 一、存档系统现状（代码事实）

- **单 key 全量写入**：`localStorage['return_star_save']`，`SAVE_VERSION = '0.5'`
- `save()`：序列化各模块 → `JSON.stringify` → `setItem`（**只对 setItem 包 try-catch**，`SaveSystem.ts:178-190`）
- `load()`：parse → 版本不匹配走 `migrate()` → 结构校验（**仅查 player/world/farm/story 四字段存在**）→ `sanitize()` 收敛非法值
- `migrate()`：**仅一行 `localStorage.removeItem()`，直接清空旧档**（`SaveSystem.ts:311-314`）
- **所有新增字段均为可选字段** + apply 内 `??` 默认值兜底（向后兼容模式扎实）

## 二、问题 1：是否存在存档污染风险 —— **存在，4 类**

### 🔴 风险 A：版本升级 = 全员清档（数据丢失，最严重）
`migrate()` 一刀切 `removeItem`，无备份、无导出。一旦 `SAVE_VERSION` 升到 0.6，所有玩家的农场/剧情进度全部丢失。注释中"宁可重新开始"是 v0.5 起步期权宜，不可持续。

### 🔴 风险 B：开发工具污染真实存档（走查 Bug 2 已确认）
`DevTestHub.ts` 经济按钮、`main.ts` 的 `debug.markRestored` 调用 `save({x:0,y:0,scene:''})`。刷新后 `MapScene.create` 检测 `scene !== 'farm'` → 空场景**黑屏**。触发需"点工具后立即刷新"，低概率但属真实污染后门。

### 🟡 风险 C：序列化异常未捕获
try-catch 只包 `setItem`，不包 `JSON.stringify` 与全部 getter。任一模块 getter 抛异常（如数据含循环引用），`save()` 会在进入 try 前抛出，**打断调用方流程**（如睡觉存档），玩家无感知。

### 🟡 风险 D：多标签页 last-write-wins
localStorage 跨标签共享，无 `storage` 事件监听、无冲突检测。两个标签同时玩，后写覆盖先写、无提示——标签 A 进度被标签 B 旧状态冲掉。

### ✅ 已做得好的（排除项）
- `deleteSave()` 后抑制 beforeunload 重写（BUG-046 修复，`SaveSystem.ts:374-379`）
- `sanitize()` 对 storyStep / questState / 数值 / robots 的边界收敛（防坏档崩溃）
- `worldRestore` 与旧 `farm.restore` 幂等合并（无重复恢复）

## 三、问题 2：是否支持版本迁移 —— 形式上有钩子，实质不迁移

| 层面 | 现状 | 结论 |
|---|---|---|
| 版本号机制 | load 时 version ≠ SAVE_VERSION → 调 migrate() | ✅ 有钩子 |
| 真实迁移逻辑 | migrate() 只有 removeItem，无逐字段搬移 | ❌ 无真实迁移 |
| 同版本字段演进 | 全部新增字段可选 + apply 默认值兜底 | ✅ 向后兼容良好 |
| 跨版本迁移 | 无迁移表、无链式迁移、无回滚 | ❌ 升版本 = 清档 |

唯一的"迁移式"逻辑是 `farm.restore → worldRestore` 合并（`SaveSystem.ts:334-340`），但它放在 `apply()` 内每次幂等执行、不升版本号——是兼容技巧，不是版本迁移。

## 四、问题 3：改进方案（最小改动，不重写）

### P0 — 防丢档（改动 < 10 行）
1. **migrate() 清空前备份**：删除前先把 raw 写入 `return_star_save_backup_<oldVersion>`，数据可抢救。
2. **save() 整体包 try-catch**：把 `JSON.stringify` + getter 纳入保护；失败保留旧档（setItem 原子，失败不半写），暴露 `getLastSaveError()` 供 UI 提示"存档失败"。
3. **load() 深层校验**：`inventory` 必须对象、`tiles/crops/trees` 必须数组，否则视为损坏档返回 null（当前只查四字段存在，坏档会崩在 apply）。

### P1 — 真实版本迁移
4. **迁移表**：`const MIGRATIONS: Record<string, (raw) => SaveData>` 链式执行（0.4→0.5），migrate() 逐级转换而非清空；转换失败 try-catch 并保留原始 raw 不删。
5. **版本号纪律**：纯新增可选字段**不升版本号**（保持现状）；只有破坏性结构变更才递增——配合迁移表，玩家进度从此不丢。

### P2 — 结构性加固（需评估排期）
6. **双槽备份**：每次 save 把上一份成功档写入 `return_star_save_prev`，主档损坏可回退。
7. **多标签防护**：监听 `storage` 事件，检测外部写入时对比 `timestamp`，提示而非静默覆盖。
8. **堵死 Bug 2 后门**：`save()` 对 `scene === ''` 直接拒绝写入（或 DevTestHub 加"测试后门勿用于真实档"守卫）。
