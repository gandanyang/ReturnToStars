## 一、移动端开发红线

### 横屏规则（最高优先级）

**归星物语不是竖屏手游。所有移动端设计必须遵守横屏优先。**

如果发现以下任何情况，**必须停止并重新确认**，不得继续：
- 竖屏布局
- 竖屏安全区处理
- 竖屏按钮排列
- 竖屏截图验收

**不要提出**"建议支持竖屏"，除非制作人明确要求。
**不要**因为"移动端优化"四个字，就默认把手机模拟成竖屏 iPhone 再改 UI。

### UI 测试纪律（AI 模拟手机时）

三步纪律，缺一不可：
1. **第一步：确认 orientation**（必须为 landscape）
2. **第二步：确认 viewport**（横屏 16:9 附近，画布等比 FIT）
3. **第三步：再评价布局**（HUD / 摇杆 / 按钮 / 安全区）

**不要基于错误模拟环境提出 UI 修改。** 在竖屏模拟器里发现的"问题"，绝大多数在横屏下不存在。

## 二、开工前三问（每次任务开始前自检）

1. **测试环境是横屏吗？**（移动端相关任务必须确认）
2. **这次改动是否触碰了已拍板决策？**（查 `DESIGN_DECISIONS.md`）
3. **是否已存在同类系统/文件？**（查 `src/systems/`、`src/data/`、`docs/`，禁止重造平行实现）

> 📌 **产品方向护栏**：凡涉及新地图 / 新 NPC / 新任务 / 新资源 / 新建筑 / 新系统 / 新剧情 / 新解锁，必须**先过 `docs/AI开发护栏-核心产品方向与成长循环-v1.0.md` 第十四节功能审核 8 问**（解决什么问题 / 改变什么 / 消耗什么 / 修复什么 / 世界变化 / 解锁什么 / 是否贴核心循环 / 是否值得成本），并优先选择轻量方案（远景 / 地标 / 一句对白 / 环境音 / 视觉变化，见护栏第七、十五节）。

## 三、通用开发红线（与 AGENTS.md 一致的硬约束）

1. **稳定 > 新功能**：不新增战斗 / 抽卡 / 大地图 / 复杂养成 / 后端；不重构架构；不替换 Phaser
2. **不重造系统**：已有 `Inventory.ts` 就不许建 `NewInventory.ts`；动手前先搜索
3. **持久状态只进 SaveSystem**；一次性事件一律 `EventManager.triggerOnce`
4. **StorySystem 单写者制**：改剧情前 git status 确认 + 不并行改同一文件
5. **Git 写权限**：禁止 `git add -A` / `git add .` / `git commit`（统一由 opencode/制作人执行）
6. **测试分级**：纯文档=Level 0 / 单系统小改=Level 1 / 核心逻辑=Level 2 / 大版本全测=Level 3
7. **语音交付流程**：先试听确认 → 更新文档 → 打包 → 装机；禁止直接打包
8. **地图 gid 语义 / 碰撞编号禁止改动**（与存档关联）
9. **剧情权限**：主角成长 / 角色身份 / 世界观真相 / 关键节点 / 玩家选择——不得自行扩写或改变
10. **爷爷设定护栏**（制作人 2026-08-10 拍板，所有 AI 生成剧情不得违反）：爷爷 = **不是隐藏真相的人，而是留下了一片等待后来者理解的土地**。禁止：爷爷秘密组织 / 爷爷隐藏巨大阴谋 / 爷爷突然成为关键谜团中心。允许：爷爷留下生活痕迹 / 价值观 / 未完成的事情。叙事方向是"理解爷爷为什么这么做"，不是"揭开爷爷的秘密"
11. **核心叙事原则**（制作人 2026-08-10 拍板，v1.2 修正，详见 `docs/design/归星岛核心叙事原则-v1.0.md`）：主线是"为什么值得有人回来"，不是"岛为什么衰落"。碎片 = 玩家与岛联系的媒介 + **钥匙**（可以开门，更要让玩家看到门后的人、土地和未来）；**允许谜底存在，但不要让谜底成为唯一价值**——允许"收集→解锁→揭示"传统结构（六根式），**结构问题 ≠ 价值问题**（结构可用成熟套路，价值不能做空；门后面必须有生活）。**关系型天命**：主角不是天命之子，而是天命回应的人；天命给予入口，行动决定结果。新区域 = 玩家行为带来的世界回应，不是地图扩张。禁止把灯塔/码头/老街写成"答案"，它们是"这里曾经有人认真生活过"的证明
12. **ComfyUI 出图默认工作流**：用 ComfyUI 生图必须默认加载 `workflow/anima_turboV10.json`（anima turbo），禁止自行新建/选用其它默认工作流；除非任务文档明确指定其它
13. **主角特殊性尺度护栏**（《天命之子之辩》v1.0，制作人 2026-08-10 拍板，详见 `docs/design/天命之子之辩-主角特殊性尺度设计原则-v1.0.md`）：主角采用"半天命、半选择"模型——特殊性 = 关系 + 条件 + 选择，**不是**天命 + 血统 + 预言。禁止写出：被世界选中 / 唯一救世主 / 爷爷早知会回来 / 碎片只等林澈 / 血统注定；第一章不得给出完整答案。允许：碎片特殊回应但不解释原因、NPC 无统一解释、靠林澈"选择留下"触发回应。稀缺性预算 ≈ 90% 普通 / 8% 关系特殊 / 2% 神秘特殊。设计剧情前必须自检：换一个普通年轻人这件事还能否发生？（A 普通 / B 关系 / C 仅林澈，C 必须极少）
14. **文本风格与反 AI 味护栏**（《归星岛文本风格与反 AI 味标准》v1.0，制作人 2026-08-10 拍板，详见 `docs/design/归星岛文本风格与反AI味标准-v1.0.md`）：新增/修改任何落到游戏里的文本（剧情/NPC 闲聊/任务/语音/文案）前必查。核心：模仿"这个作品里一个具体的人在具体情境下会说的一句自己的话"，不是生成漂亮句子。禁止：作者替角色总结主题 / 角色发表"主题演讲" / 每句都服务剧情 / 核心词成为 NPC 口头禅（回应/留下/记住/未来/命运/答案/意义等需稀缺）/ 角色说出自己不该知道的信息。每个角色必须有说话缺陷、有自己的语言指纹（对照标准第五章六角色表）。硬指标：**遮掉名字能否猜出是谁**，猜不出=返工。流程：人定声音→AI 扩写→AI 自检→人挑选→一致性检查→人工定稿
