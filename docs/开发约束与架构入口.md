# 《归星物语》开发约束与架构入口

> 目的：防止 AI / 开发过程中**重复创建类似系统**。新增功能前必须检查已有能力，不允许无理由创建平行实现。
> 阅读顺序：`docs/AI开发前必读.md`（门禁）→ 本文件 → 对应任务文档（`docs/tasks/…`）。

---

## 一、核心原则

### 1. 状态不要散落

禁止分别用 `localStorage.xxx` / `scene.xxx` / `global.xxx` 保存同一种游戏状态。

所有持久状态必须收口到 **`SaveSystem`**（`SaveData` 结构：player / world / farm / story / mapFlags / album / gameState.triggeredEvents）。

- 场景内需要持久化的状态走 `MapSceneFlags`（随 `SaveSystem` 序列化，旧档可选字段默认空）。
- 会话级状态（刷新即丢）必须注释说明"仅本次游玩"，不得冒充存档状态。

### 2. 存档版本维护原则（SaveSystem v0.5+，2026-08-17 制作人拍板）

`SAVE_VERSION` 是**存档格式契约**，改动 = P0 敏感，**禁止 Agent 自作主张升级版本号**。遵循四条硬性原则：

1. **新字段优先「可选 + 默认值」兼容**：新增存档字段一律加 `?`，`apply()` 内用 `?? 默认值` 兜底（旧档无此字段正常运行）。此模式无需升版本号。
   > 例：`natureDiscovery?` / `worldRestore?` / `gameState?` / `chapter?` 均为可选 + 默认值，天然向后兼容。
2. **只有破坏性结构变更才提升 `SAVE_VERSION`**（如字段被移除 / 重新分组 / 类型语义改变）。仅新增字段**严禁**升版本号。
3. **版本迁移前必须先备份旧档**：`migrate()` 清档前写入 `return_star_save_backup_<oldVersion>`，绝不静默 `removeItem`。
4. **禁止写入非法 `player.scene`**：`save()` 对 `scene === ''` 拒绝写入并返回 false（防开发工具污染真实存档导致黑屏）。开发工具改状态应走 `devSave()`（保留玩家真实位置），不得写 `save({x:0,y:0,scene:''})`。

> ⚠️ **红线**：任何 Agent 不得以"顺手""重构"为由把 `SAVE_VERSION` 改成 `'0.6'` 或移除现有存档字段。必须升版本时，写真实逐字段迁移逻辑 + 备份 + 制作人批准。参考 `docs/reports/存档系统风险分析与迁移方案-2026-08-17.md`。

### 3. 一次性事件统一入口

以下内容**必须优先使用 `EventManager.triggerOnce(id, fn)`**：

- 剧情触发 / NPC 特殊事件 / 相簿解锁 / 记忆卡获取 / 隐藏彩蛋 / 支线完成奖励

禁止只判断条件就触发而不记录"已触发"：

```ts
// ❌ 只判断条件，刷新后可能重复触发
if (day === 3) { triggerEvent(); }
```

必须：

```ts
// ✅ 触发一次 + 状态随存档恢复
EventManager.triggerOnce('event_id', () => { runEvent(); save(); });
```

## 二、新增系统前检查清单

执行任务前必须回答：

1. **是否已有类似功能？** 先查 `src/systems/`、`src/data/`、`docs/tasks/`、`docs/design/`。
2. **数据放哪里？**

   | 类型 | 位置 |
   | --- | --- |
   | 永久状态 | `SaveSystem`（SaveData / mapFlags / gameState） |
   | 配置数据 | `src/config` / `src/data` |
   | 临时表现 | scene / local（刷新即丢，需注释） |
   | UI 状态 | UI 层（`src/ui`） |

3. **是否可以扩展已有系统**（修改）而不是新增平行实现（NewSystem2）？

### 4. 剧情事件调度检查（StoryDialogue 单实例对白，2026-08-11 制作人拍板）

当前：`StoryDialogue` 是**单实例对白播放器**（`MapScene.showDialogue` 共用入口 + `showMemoryMoment` 全屏旁白并存）。同一时刻只能有一个剧情在播——**后调用的 `play()` 会覆盖正在播放的对白**（历史事故：Dialogue Handoff 覆盖、BUG-073 day2 清晨演出 vs 首次收获）。

新增剧情事件 / 演出 / 自动对白前，必须回答：

1. **是否可能与已有演出同时触发？**（定时器 / 场景切换 / 多触发点重叠）
2. **是否需要等待？** 当前对白播完再播（如 BUG-073 轮询守卫：`isOpen()` 每 200ms 检查，20s 兜底）
3. **是否需要排队？** 延后到当前演出结束再补播（如 BUG-073 `pendingFirstHarvest` 补播链）
4. **是否允许覆盖？** 默认**禁止**。

**禁止：直接 `storyDialogue.play()` 覆盖正在播放的对白。**

已有调度机制（复用而非重造）：

- 演出窗口标志（`firstMorningActive`）+ 窗口内抑制 + 结束补播
- 播放前 `isOpen()` 检查等待（轮询守卫）

> Alpha Freeze 纪律：**先形成规则，不重构**。不得因类似问题升级为「重写对白系统 / 引入事件队列」。

## 三、当前核心系统地图（入口）

| 能力 | 入口文件 | 负责 |
| --- | --- | --- |
| 存档 | `src/systems/SaveSystem.ts` | 玩家/世界/解锁/一次性事件状态（SaveData） |
| 剧情 | `src/systems/StorySystem.ts` | 主线步骤 storyStep、剧情对白数据 |
| 主线任务 | `src/systems/QuestSystem.ts` | 星之碎片任务状态机 |
| 每日任务 | `src/systems/DailyQuestSystem.ts` | 每日随机任务池 |
| 一次性事件 | `src/systems/EventManager.ts` | triggerOnce / hasTriggered / 存档恢复 |
| 解锁 / 相簿 | `src/data/PhotoAlbum.ts` | unlockPhoto（幂等）+ album 存档 |
| 场景一次性 flag | `MapSceneFlags`（`src/scenes/MapScene.ts`） | 场景状态随存档持久化 |
| 世界恢复 | `src/data/FarmRestore.ts` | 花园/老屋/道路恢复状态 |
| NPC | `src/systems/NPCSystem.ts` | NPC 作息 / 站位 |
| 音效氛围 | `src/systems/AmbienceSystem.ts` | 昼夜/雨天环境音 |
| Debug | `main.ts` 的 `window.debug` | 测试钩子（探针用） |

## 四、AI 开发规则

收到需求时**不要直接编码**，先输出：

```diff
已有系统检查:
- 是否存在类似功能:
- 复用方案:
- 新增文件:
- 修改文件:
```

确认后再施工。施工前先读相关文件，找最小修改点。

## 五、禁止事项

1. 新建第二个 `SaveManager` / `SaveSystem2`。
2. 新建第二个 `EventManager` / `EventService` / `QuestTrigger`。
3. 在 Scene 里直接写 `localStorage` / `global` 保存永久状态。
4. 用临时变量代替存档状态（会话级需注释并接受刷新丢失）。
5. 为单个 NPC 创建独立管理器（除非明确需要）。
6. 无任务要求的"行为不变重构"（稳定优先，重构需任务明确收口目标）。

## 七、ComfyUI 生图默认工作流（硬性）

- 使用 ComfyUI 生图时，**默认加载 `workflow/anima_turboV10.json`**（anima turbo 工作流）。
- 这是唯一默认工作流；除非任务文档明确指定，否则禁止自行新建/选用其它 ComfyUI 工作流（避免风格不统一）。
- 出图任务开始前先确认 `workflow/` 目录文件。
