# EventPlan 准备系统设计方案 v0.1

> 状态：📋 制作人方向稿（2026-08 提供，待落地实例）
> 关联：`星光艺术展-垂直切片设计稿-v0.2-拍板基线.md`（第一个 EventPlan 实例模板）、`丰收节-垂直切片设计稿-v1.0.md`（v1.5 第二个实例，待拍板）、`庆典筹备系统设计-v0.2-拍板方向.md`
> 核心立场：**EventPlan 不是任务列表，是"小镇生活状态系统"。**

---

## 一、系统定位

EventPlan 不是任务列表。

不是：

```
□ 收集10个玉米
□ 收集5条鱼
□ 收集20木材
```

而是：

> 青禾镇正在为某件事情做准备。

玩家看到的是一个正在变化的小镇。

### 核心循环

```
日常生活行为 → 获得生活资源 → 帮助居民完成准备 → 世界状态变化 → 活动发生 → 永久留下痕迹
```

---

## 二、EventPlan 数据结构

每个活动拥有：

```ts
interface EventPlan {
  id: string;
  title: string;
  phase: 'preparing' | 'active' | 'aftermath' | 'completed';
  preparations: Array<{
    type: string;   // 'env' | 'people' | 'resource'
    name: string;
    state: string;  // 完成态/文案
  }>;
}
```

## 三、三类准备

不要按照"材料数量"分类，按照"小镇需要什么"分类。

### ① 环境准备

关键词：让地方重新像一个要举办活动的地方。

例·春日集：
- ❌ 收集20木材
- ✅ 环境准备：
  - [完成] 旧摊位重新搭起来 → 效果：广场出现木质摊位
  - [完成] 河边长椅修好 → 效果：居民晚上会坐在那里

例·秋日晒场：
- [完成] 旧晒场清理完成 → 出现晒架
- [完成] 木架修复完成 → 出现鱼干架

玩家不是交材料，玩家是在帮助这个地方恢复。

### ② 人际准备

这是《归星物语》和星露谷最大的区别。不是"找三个人交东西"，而是让居民重新参与生活。

例·秋日晒场：
- 老张：需要有人帮忙恢复晒鱼手艺 → 完成：老张会出现在晒场
- 夏雅：整理过去的照片 → 完成：晒场出现旧照片展示
- 阿风：提出让外面的人看看这里 → 完成：埋下第三章商业化矛盾

### ③ 资源准备

保留星露谷献祭的"准备感"，但是改成"今年有什么可以拿出来"而不是"交付物品"。

例·秋日晒场：
- 玉米：玩家种出的第一批收成
- 鱼：玩家钓到的河鲜
- 野花：玩家采集的季节花
- 蔬菜：玩家种植成果

重点：这些东西不是消耗品奖励，它们代表"今年青禾镇留下了什么"。

## 四、准备状态显示

不要显示：

```
秋日晒场
0/10 玉米
0/5 鱼
0/20 木材
```

改成：

```
秋日晒场

今年的收成，有人想拿出来晒一晒。

环境：
✓ 晒架已经搭好

居民：
✓ 老张准备好了晒鱼的方法

收成：
✓ 玉米已经送到了晒场

距离开始：准备完成
```

---

## 五、活动解锁逻辑

不用数值、不用等级、不用好感，使用**世界事件条件**。

例·秋日晒场：

```
春日集完成
+ 第一次收获玉米
+ 晒场相关居民事件完成
→ EventPlan activated
```

---

## 六、准备过程中的世界反馈

准备不是菜单里的数字变化。准备期间：

- 每天 NPC："老张最近一直在晒东西。"
- 地图："广场多了一些木架。"
- 环境："河边多了晾晒的鱼。"

玩家感觉：小镇正在准备。

---

## 七、活动完成后的永久状态

活动结束不是"获得100金币"，而是世界改变。

例·秋日晒场·永久：
- 青禾晒场（新增区域视觉）
- 晒鱼架 / 收成展示台 / 长桌 / NPC停留点 / 商店新增本地食材

以后 NPC："今年晒场也快开始了。"

---

## 八、和星露谷献祭的区别

| | 星露谷 | 归星物语 |
|---|---|---|
| 链路 | 玩家贡献资源 → 社区设施恢复 | 玩家参与生活 → 居民重新连接 → 小镇恢复记忆 |

核心不是"完成收集"，而是"今年，我们一起留下了一些东西。"

## 一句话总结

> EventPlan 的准备系统不是任务系统，而是"小镇生活状态系统"。玩家不是完成活动要求，而是在活动发生前，让世界逐渐变成适合这个活动的样子。每一次准备都会留下永久痕迹。
