## 一、走查的定位：唯一问题

这不是功能验收，不是回归测试，不是找 bug。

**唯一问题**：

> 这 15～30 分钟，有没有让你产生「我还想继续」的冲动？

判断不靠"功能挺完整"，靠**玩家的真实感受**。若答案是"有"→ 值得继续打磨；若答案只是"功能挺完整"→ 说明还有体验债务。

**明确不做**：
- ❌ 不重跑探针 / 不检查代码正确性
- ❌ 不做功能清单式核对（"这个系统有没有"）
- ❌ 不提出大规模重构 / 不加新功能
- ❌ 不碰工作区冻结的残留改动

## 二、走查准备

| 项 | 建议 |
|---|---|
| 设备 | 移动端真机横屏为最终目标；无真机时用 PC 浏览器桌面视口（1024×768）代验，但移动端为准 |

| 记录 | 手边记事本/备忘录，**随时记"当时的原话感受"**，不事后回忆 |
| 时间标记 | 记录游戏时钟（第几天 / 几时）+ 场景名，便于日后定位 |
| 心态 | 以"第一次玩这个版本"的玩家身份，不看提示、不查文档 |

## 三、走查流程：两遍法

### Pass 1 — 完整新档第一遍（最真实）

全新存档从头跑完整条链，重点看**衔接**和**节奏**：

```
观星夜 → 第一声回应 → 镇长介绍 → 老屋整理 → 镇长来访
      → 集市恢复 → 春日集
```
穿插：捉虫 → 昆虫观察 → 夏雅·一 → 旧日留影

预估 15～30 分钟。这一段能看到"这些内容放在一起到底是不是一个完整舒服的游戏"。

### Pass 2 — 种子跳转复核（分段复查）

用 Dev Test Hub（`?devHub=1` → 车站公告栏 → 按 E）跳种子档，**单段重放**，专门复核下面四段，每一段只问"这一段单独拿出来，好玩吗"：

| 种子 | 复核点 |
|---|---|
| 观星夜完成 | 第一章开场是否给出期待感（第一天为什么醒来） |
| 第一声回应 | ch0→ch1 的情绪是否自然延续 |
| 老屋整理完成 | 整理完有没有"我让老屋活过来"的反馈 |
| 集市恢复前 / 后 | 布置→开张的世界反馈是否够震撼（灯亮/人来/音乐） |
| 春日集 | 第一章情绪收束是否成立 |

> 若 Pass 1 已很清晰，Pass 2 只挑最模糊的 1～2 段即可，不必全跑。

## 四、分段观察清单（核心）

以下每一段都只需回答一类问题：**"此刻我作为玩家的真实感受是什么"**，而非"功能对不对"。

### 段 1：观星夜 → 第一章开场
- 从 ch0 收尾到 ch1 醒来，情绪有没有断？
- 醒来后，我第一反应是想"出去看看"，还是"不知道要干嘛"？

### 段 2：老屋整理（床 / 灯 / 书桌 / 收音机）
- 我**为什么**现在要整理老屋？（有动机，还是"地图上有高亮就去点"）
- 整理每一样东西时，有没有"这是爷爷的东西"的触感，还是"清任务清单"？
- 每件之间是否有节奏呼吸（B-1/B-2/B-3 是否真的解决"装修清单感"）
- 整理完成后，环境有没有"回馈"我？（光 / 氛围 / 声）

### 段 3：镇长来访
- 来访是"自然发生"还是"突然弹窗"？
- 镇长说完后，我是否产生"接下来该干嘛"的**主动**念头？

### 段 4：捉虫引导（发现自然）⚠️ 重点
**核心测试**：玩家有没有觉得——
> "我为什么现在要捉这个？"
而不是
> "系统让我捉，所以我捉。"

- 触发时机是否自然（路过河边/老屋/果林时被"等等，你看那里"吸引）？
- 捕捉交互有没有手感（想不想再试一次）？
- 首次奖励是**世界观文本**而非金币——读那段文字时有没有触动？

### 段 5：集市恢复（参与小镇生活）⚠️ 重点
- 这段从"单纯叙事"过渡到"**我正在让镇子恢复**"，有没有真的感到"是我在做"？
- 布置时是否在"听居民需求"（放错→温和纠正，不惩罚），还是变成"猜谜"？
- **开张那一刻**：灯亮 / 人来 / 音乐响起——"这是我第一次真正觉得岛活过来了"是否成立？
  - 这是整个第一章的核心验证点：**我做了一件事 → 这个地方真的变了**。

### 段 6：昆虫观察（理解自然）⚠️ 重点
**最容易"看起来有玩法，实际很机械"的一段**。重点观察自己：
> "还挺有意思，我想再看看"
还是
> "赶紧让我点完。"

- 每次观察是否给出**新信息**（翅膀/活动时间/环境，三者是否真有区别感）？
- 填自然笔记有没有意义，还是纯走流程？
- 收束台词"原来它们一直都在"有没有落点？

### 段 7：春日集（收束）
- 夜晚演出 + 人群环境音，是否强化了"这个镇子有声音了"？
- 作为第一章终点，情绪是否给到"我还想看看它以后的样子"？

### 穿插项：夏雅·一 / 旧日留影
- 是否自然融入主线，还是打断节奏？
- 有没有让人觉得"这镇里的人开始有故事了"？

## 五、四条红线问题（走查全程反复自问）

1. **① 我什么时候开始觉得「这里正在恢复」？**
   —— 若直到集市才第一次明显感到"哦，真的在变"，前面几段的反馈就有问题。
2. **② 我有没有"主动"想去做下一件事？**
   —— 不是"任务告诉我去哪"，而是"看到那个东西就自己想过去看"。
   这是「生活游戏」与「任务模拟器」的分水岭。
3. **③ 三个轻玩法有没有真正产生差异？**
   —— 不能是"捉虫小游戏→集市小游戏→观察小游戏"排队；
   应是「我发现岛上还有自然 → 我开始参与这里的人们生活 → 我开始理解这里为什么值得留下」。
4. **④ 做完一件事后，有没有"刚才是我让这里发生了变化"的感觉？**
   —— 行动是否有世界反馈。这个比再加一个小游戏重要得多。

## 六、记录表

每记一条，尽量用**玩家的原话**，别自己总结成"挺好/还行"。

```
时间点(第几天/几时) | 场景 | 我在做什么 | 我的真实感受(原话) | 问题类型 | 严重度
```

**问题类型**（五类，参考定调文档）：节奏 / 空洞 / 引导 / 世界反馈不足 / 没有探索欲

**严重度**：高（不想继续玩或明显不适）／中（轻微别扭）／低（可忽略）

**额外标记「冲动时刻」**：任何时候感到"我想再试试 / 我想过去看看"，单独标 ⭐ —— 这些是**好迹象**，走查后要保住，别在后续修改中弄丢。

---

## 七、走查后决策流程

1. 汇总所有记录，按 **严重度 + 频次 + 是否命中红线问题** 排序。
2. **只挑前 3 个最高价值问题**（不要全修）。
3. 给 AI 的修复指令要带：玩家原话证据 + 问题类型 + 期望感受，而不是"把 X 改大点"。
4. 修复后由制作人**复走那一段**，确认感受改善后再进入下一步。
5. 只有在"好玩"成立之后，才讨论第一章正式内容（夏雅·二 / 新事件 / 新区域 / 其他玩法）。

> 决策原则：**现在不需要更多内容，只需要回答"有没有让人还想继续"。**
> 答案有 → 打磨；答案只是"功能完整" → 那是体验债务，继续找。

---

## 八、走查中禁止做的事（自我约束）

- 不修 bug、不改参数、不截图研究渲染（那是后面的事）
- 不问 AI 某个系统"有没有做对"——本次只看"玩起来"
- 不因为"还有空"就顺手加 QTE / 小游戏 / NPC / 地图
- 遇到卡死/真 bug：记一笔继续走，不要当场调试
