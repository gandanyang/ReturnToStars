## 〇、制作人提案（原文要点）

- 类似开罗游戏的"定时举办庆典"功能，在春日大集以后解锁。
- 在菜单里决定接下来一段时间，村子要为某个大型事件做准备。
- 例子：某个艺术家要来村子办艺术展；举办可以实时直播的村超（篮球/球赛）。

---

## 一、系统定位

一句话：

> **不是"办活动"，是镇子为了一个外人会来的理由，一起生活一段时间。**

这是核心循环第五步"被看见 / 新的人回来"的**主动版**——玩家不再只是"让镇子变好，等它被想起"，而是**主动决定镇子被什么想起**。

与第二章《故人远来》完全同构：外来者因为某件事而来；玩家可以主动为这件事做准备。

---

## 二、机制骨架（方向层）

1. **选择事件**：菜单里选择一个事件类型（艺术展 / 村超 / 市集夜 / …），每种对应一个"被看见的方式"和一个"想来的客人"。
2. **筹备期（3-5 游戏日）**：镇子出现"筹备需求"——**全部来自现有玩法产出**（作物/采集/钓鱼/交换/木头/花）。
3. **筹备期反馈**：逐日世界变化（挂灯、搭台、居民排练、孩子试球）——不是任务板，是"镇子在为它准备"。
4. **事件当天**：仪式性时刻（克制演出，复用章节终点范式，规模 ≤ 春日大集）。
5. **事后**：世界变化（新的人留下 / 被记住 / 新机会）+ 第三章埋线（"外面有人看到后想更多"）。

---

## 三、关键设计决定（建议，待拍板）

1. **一次性生活时刻**：每个事件只办一次，不重复、不可反复优化——避免变成"经营收益题"（哪个庆典划算选哪个），守住"不是数值游戏"定位。
2. **无对错选择**：不同事件给镇子不同的"被看见方式"，各有代价与收获；游戏不评价哪个更好（呼应"游戏不评价哪种选择更正确"）。
3. **筹备需求收编现有玩法**：这是核心循环的"事件版"收口——例如艺术展需要花（采集/花田产出），顺带补上采集玩法只有"卖"的缺口。
4. **"直播" = 叙事表现**：村超直播表现为"外面的人在看"（旁白/信件/新来的人），**不做真实联网**——符合"禁止引入后端"红线。

---

## 四、与章节的关系

- **解锁**：春日大集（`ch1_spring_fair`）完成之后。
- **第二章落地**：外来者（老木匠 A / 记录者 B）来了之后，玩家可以主动办一场"让镇子被看见"的事——艺术展天然连接 B 的影像档案。
- **第三章引信**：事件让镇子被看见 → 有人想"放大"这种被看见 → 商业化与本土情怀的争议从这里长出。
