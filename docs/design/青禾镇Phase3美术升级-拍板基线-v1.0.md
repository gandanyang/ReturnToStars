## 一、制作人拍板总评（原文要点）

> 这份方案是目前整个青禾镇重构里**最接近正式游戏制作流程的一版**。
> 前面在解决"地图怎么铺"，现在开始解决"地图怎么活起来"——这已经不是 Tilemap 编辑问题，而是**环境叙事设计（environmental storytelling）**。

**核心判断**：
- 《归星物语》的核心不是"模拟一个真实小镇"，而是"让玩家感觉这个小镇曾经有人生活"
- 第0章 + 第1章 + 15~30 分钟体验的体量，不需要"大而全"的城镇 tileset
- GameObject 天然适合"这个地方恢复了"的状态变化语义

## 二、路线决策：C（混合路线，已拍板）

| 项 | 决策 |
|---|---|
| tileset 扩展 | ❌ **不扩**（保持 16 gid 不变） |
| 衰败态表达 | tile（现有 gid8 花丛 / gid14 栅栏 / gid13 井 / gid10 墙等） |
| 修复态表达 | GameObjects 独立 sprite（增删切换，不碰 tile） |
| 数据源唯一 | ✅ 遵守 MapExpansion.md §三（零 GID 漂移风险） |

**不扩 tileset 的深层理由**（制作人原话）：
- 扩 tileset 会进入"为每个物件加一个 tile"的危险方向，最终变成维护大型素材库
- GameObject 更适合本游戏的变化本质："这个地方恢复了"（状态变化，非地图变化）
- 例：S4 老屋 衰败态(残墙+荒草+废井) → 修复态(+灯光+花坛+温暖) 是状态叠加，GameObject 天然适配

## 三、首批资产优先级（制作人调整，已拍板）

**总原则**：Phase 3 不追求"美"，目标只有一个——
> 玩家第一次走进青禾镇，感觉这里不是一张地图，而是一座曾经有人生活过、现在等着重新亮起来的小镇。

### 资产优先级（调整后）

| 优先级 | 资产 | 复用块 | 叙事价值 |
|---|---|---|---|
| **P0-1** | 路灯（点亮态） | S1 镇门 / S4 老屋 / S6 河堤 / S7 集市 | "灯亮"=《归星物语》核心意象（从冷清到有温度的最直接视觉语言） |
| **P0-2** | 招牌（挂回态） | S2 老街 | "这里曾经有生活"（空招牌→挂回招牌，玩家马上理解"以前营业过"） |
| **P0-3** | 长椅 | S6 河堤 | "玩家愿意坐下来的地方"（非战斗游戏，停留空间极其重要） |
| **P1-1** | 窗灯（亮灯态） | S2 老街 | "有人回来"（依赖建筑，排在路灯后） |
| **P1-2** | 花坛（修复态） | S4 老屋 / S6 河堤 | "有人生活"（易变装饰，最后做） |

**调整理由**（制作人原话）：
- 招牌提前：窗灯表达"有人回来"，招牌表达"这里曾经有生活"——叙事价值更高
- 长椅提前：游戏不是战斗游戏，玩家停留空间非常重要；河边没长椅=地图，有长椅=玩家愿意坐下来的地方
- 花坛最后：花坛容易变成装饰；第一阶段重点不是漂亮，是"有人生活"

### 实际产出回填（2026-08-13，管线验证后逐步回填）

| 资产 | sprite 入库 | 规格 | 说明 |
|---|---|---|---|
| P0-1 路灯 | `public/assets/sprites/lamp_pointed.png` | 17×48, 23 色 | GPT v2 黑底 → 抠图 → 量化入库 |
| P0-2 招牌 | `public/assets/sprites/sign_hung.png` | 55×48, 19 色 | GPT v2（v1 被安全拦截，改措辞绕过） |
| P0-3 长椅 | `public/assets/sprites/bench.png` | 37×32, 20 色 | GPT v1 一次通过 |
| P1-1 窗灯 | `public/assets/sprites/window_lamp.png` | 47×48, 21 色 | GPT v2（v1 画成"整面墙+窗"实心块，v2 强调"only the window, no wall"后为纯窗形态） |
| P1-2 花坛 | `public/assets/sprites/flowerbed.png` | 61×32, 21 色 | GPT v1 一次通过（木箱+土+暖色花） |

**生产管线**（`tools/sprite_process.py`，路灯验证后固化）：
`GPT-image-2 黑底图 → 黑→透明(阈值18/36羽化) → 裁剪包围盒 → 等比缩放(NEAREST) → 量化24色(NONE无抖动) → 入库`
- GPT 输出是"像素插画"（316 色含渐变）→ **量化后 19~23 色**达到游戏资产级
- 每张 $0.088（1024×1024 medium）；招牌 prompt 含 sign/text 措辞易触发安全拦截，用"hanging wooden board"绕过（已在 `prompts/sign_hung_v2.txt` 固化）

## 四、声音绑定（制作人新增要求）

> Phase 3 不全是视觉。项目优势之一是 WebAudio + 氛围。环境物件最好绑定声音。

**核心目标**：游戏核心不是"看"，是"让玩家觉得自己在那里"。

| 舞台块 | 视觉物件 | 绑定声音 |
|---|---|---|
| S6 老河堤 | 长椅 + 花 | 水声增强 |
| S7 集市广场 | 摊位 | 远处人声 |
| S4 老屋宅基地 | 灯亮 | 轻微木门声 / 风声 |

**施工约束**：
- 声音绑定走现有 AudioSystem 范式（不新增音频系统）
- 音量克制，不抢戏（参考观星夜音效纪律）
- 触发时机与 GameObjects 修复态同步

## 五、GameObjects 数量上限（已拍板）

| 维度 | 上限 | 理由 |
|---|---|---|
| 每块独立 sprite | ≤5 个 | 50×35 非开放世界，每块一个记忆点即可 |
| 全图总计 | ≤30 个 | 避免"每平方米都有东西"的原神开放世界错误 |

**设计哲学**：一个地方有一个记忆点，不是堆砌装饰。

| 性能 | 每块独立 sprite ≤5 个，全图 ≤30 个 | 运行时 FPS 监控 |

### 7.2 新增验收：停留测试（制作人拍板）

> 现有验收："可读的过去证据"——很好。
> 再加：**玩家是否会主动停下来。**

**测试方法**：
让一个**没看过设计文档的人**进入青禾镇，观察 5 分钟内行为：

- [ ] 有没有主动靠近河边？（S6 河堤吸引力）
- [ ] 有没有停在老屋？（S4 老屋吸引力）
- [ ] 有没有看镇牌？（S1 镇门吸引力）
- [ ] 有没有绕去老街？（S2 老街吸引力）

**判断标准**：
- 有主动停留 → 说明空间开始有吸引力（通过）
- 全程直奔任务点不停留 → 空间无吸引力（不通过，需返工）

**设计哲学**（制作人原话）：
> 游戏卖点不是探索奖励，而是治愈。所以测试"玩家是否会主动停下来"。

## 十三、声音绑定完成回填（2026-08-13，§四 S6 水声增强）

**需求**：S6 老河堤水声增强——位置触发（不能全局播），复用 AmbienceSystem 程序合成原语（§九.2：不新增音频系统）。

**实现**（`src/systems/AmbienceSystem.ts` + `src/scenes/MapScene.ts`）：
- `AmbienceSystem`：
  - 新增 `case 'water'` 循环层：中低通噪声（filterFreq 520）+ 缓慢起伏（lfoHz 0.2 ≈ 5s 一波），比 waves 更近更连续（河道流动感），音量 0.022 不压操作音效
  - 新增 `setRiverProximity(near)`（与 `setRain` 同范式）：`riverNear` 意图持久 + `riverNode` 即时创建/移除；`stop()` 清 `riverNode` 引用（意图保留）；`start()` 重建时检测 `riverNear && town` 恢复
  - 仅 `activeMap === 'town'` 叠加；非 town 地图靠近只记录意图
- `MapScene`：
  - 新增字段 `riverSoundNear`（状态缓存，变化才调用 setRiverProximity，幂等 + 零开销）
  - `update()` 每帧检测：`mapKey==='town' && player.x < 6*TILE && player.y ∈ (5*TILE, 30*TILE)`
  - 触发矩形依据：town 扩容后（50×35）S6 河在 Walls 层 **cols0-4 × rows6-28（gid4 水，碰撞）**，长椅 (5,15) 即西岸第一列可站立地；左上角草地（rows0-5）x 虽小但 y 不达标不误触发

**验证**（新探针 `tests/probes/probe-phase3-river-sound.mjs`）：
- `tsc --noEmit` EXIT=0
- **15/15 通过**：
  - 段A 模块级 9 项：town 白天基础 2 层（voices+wind，**birds 为事件音不进 playing**）、靠近 +1、远离回落、重复 true 幂等、stop 清空、意图保持（stop 后重进 town 恢复）、非 town 不叠加
  - 段B 集成 5 项：AudioSpy 节点计数——瞬移河边 (88,248) → `riverSoundNear=true` + buf/flt/osc 各 +1（河声层真实创建）；瞬移回中央广场 → 回落 false
- 回归 `probe-phase3-restoration.mjs` **10/10 通过**（Phase3 对象零影响）
- 截图：`tests/probes/test-screenshots/phase3-river-bench.png`（河边长椅目测）

**探针踩坑记录**（§十二 之外新增）：
- `start()` 首行检查全局声音总开关 `isSoundEnabled()`（默认静音）→ 探针必须先 `setSoundEnabled(true)` 再测，否则 count 恒 0
- enterTown 的 `page.reload()` 会清掉 `window.__spy`/动态 import 的模块引用 → AudioSpy 必须**进 town 之后**再装
- 进 town 可能带开场对话：`storyDialogue.isOpen()` 时 update 提前 return，位置检测暂停（对话中玩家本就不可移动，属正常）→ 探针先 `storyDialogue.reset()` 再测
- Vite dev 下动态 import 与游戏静态 import 是**不同模块实例**：段A 测独立实例模块逻辑（getSourceCount 增减），段B 用全局 AudioContext.prototype 计数测游戏实例集成
