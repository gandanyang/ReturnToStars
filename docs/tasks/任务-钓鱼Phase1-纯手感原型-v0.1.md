## 一、目标

验证钓鱼机制本身好不好玩——**先验证手感，不接经济 / 交换 / 剧情 / 世界反馈**。

> 等待舒服 → 自然理解何时收竿 → 成功瞬间有爽感。

设计原则：**操作简单，等待舒服，判断有趣，成功爽快，失败不烦。**

---

## 二、范围（Phase 1，严格照《施工规范》）

1. **一个钓点**：S6 老河堤（town 西侧 x5 列岸线，长椅附近）；轻量交互提示「钓鱼」；**不新增独立钓鱼场景、不切复杂 UI**，玩家留在当前地图空间，结束后恢复正常移动。
2. **一种鱼**：青禾鲫（纯手感测试鱼）。
3. **循环**：

```text
进入钓点 → 甩竿（0.5~1s）→ 等待（2~5s）→ 浮漂反馈
  → 试探假动作（30%）或直接真咬钩（70%）
  → 真咬钩明显下沉 → 0.6~1.0s 收竿窗口
  → 成功（0.5~0.8s 反馈：浮漂下沉/收竿/水花/鱼跳出）或失败（鱼跑，立即重试）
```

4. **成功结果**：获得青禾鲫 ×1（按《施工规范》§16 成功结果 = Inventory +1；若排期紧张，先以"获得提示"呈现，正式 Inventory 归 Phase 3）。
5. **失败**：鱼跑掉，立即允许再次钓鱼；**不扣血 / 金币 / 鱼饵 / 冷却**。

## 五、技术约束（零新系统）

| 能力 | 复用 / 落点 |
|---|---|
| 交互 | MapScene `tryInteract` 范式 + `setupFishingSpot`（新方法） |
| 状态 | 场景内会话状态（刷新即丢，注释说明）；**零新顶层存档字段** |
| 成功结果 | Inventory（或先获得提示，见 §二.4） |
| 音效 | WebAudio 程序合成：等待安静（水声/风声）/ 试探极轻 / 真咬钩明显强于试探 / 成功=最重要反馈 |
| 表现 | Graphics 程序绘制（浮漂 / 水花 / 波纹 / 鱼跳出），零新素材 |
| 参数 | 单一配置点（可调参数集中，不散落写死） |
