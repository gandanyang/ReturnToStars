# 一、开发目标

第一章不是新增大量系统。核心目标：

> 让玩家第一次感受到"自己的行动正在让青禾镇恢复生活"。

技术目标：基于已有 Demo 系统扩展——章节控制 / 世界状态变化 / 条件事件 / 场景恢复 / NPC 状态变化。

禁止：重做已有系统 / 引入大型新框架 / 复杂装修系统 / 大型经营系统。

# 三、开发原则

1. **优先复用已有能力**：EventManager / FarmRestore / MemoryFlashback / NPC Dialogue / Save System 优先扩展，不重复实现。
2. **所有变化必须可感知**：禁止只改变量。`marketSquare=true` 必须伴随 → 地图变化 → NPC 变化 → 对白变化。

## P0-0：Town 地图空间重构（第一章前置，制作人 2026-08-12 拍板）

### 背景与判断

当前 Demo 地图结构是为**验证玩法**设计的；第一章开始需要承载"生活感+复兴感"。继续往 30×20 小地图塞（老屋/集市/NPC 活动/公共区域变化）会导致：

> **内容密度上升，但空间感下降**——"怎么所有东西都挤在一个院子里？"

这与《归星物语》想表达的"小镇生活"冲突。**解决方案不是加新地图，而是地图空间重构**：

> 旧 town（30×20）→ 扩展为完整青禾镇（建议 50×35 或 60×40）

### 为什么比新地图更好

| 方案 | 玩家感受 |
|---|---|
| 突然解锁新区域 | "这是冒险游戏" |
| **原来青禾镇还有这些地方** | **"这是生活游戏"** |

### 目标布局（示意）

```
        北 ↑
    森林入口（不变）
        │
老街 ── 集市广场 ── 商店街
        │
     林澈老屋
        │
      车站入口（不变）
```

### 工程风险（为什么不能直接改）

扩地图比加新地图风险更高，涉及：碰撞 / NPC 坐标 / 摄像机边界 / 寻路 / 出入口 / Tiled 地图。**不一次性做完**，分两阶段：

| Phase | 内容 | 原则 |
|---|---|---|
| **Phase 1（第一章必须）** | 只扩 town 空间，不增加大量内容 | 解决拥挤；基础设施不是内容开发 |
| **Phase 2（填充）** | 集市广场（第一章）/ 老街（未来 NPC 生活）/ 河边（未来钓鱼）/ 空地（未来小游戏） | 地图成为容器，内容随章节填充 |

### 技术方案（代码级核验 2026-08-12）

| 项 | 现状 | 改动 |
|---|---|---|
| Tiled 地图 | `town.json` 30×20，Ground/Walls 两层（`public/assets/maps/town.json`） | 扩为 50×35 或 60×40（Ground/Walls 数据数组扩容，新增区域用空瓦片 gid 0） |
| 物理世界边界 | `MapScene.ts:876` `physics.world.setBounds(0,0,map.widthInPixels,...)` | ✅ 自动适配（从 map 尺寸读取） |
| 相机边界 | `MapScene.ts:913` `cameras.main.setBounds(...)` | ✅ 自动适配（map.widthInPixels） |
| NPC 坐标 | `NPCSystem.ts` SPOTS.town（硬编码像素点） | ⚠️ 需按新布局平移（7 NPC 站位，错开集市区） |
| 出口 | `src/data/exits.ts` town 出口（左→farm/顶→mine/右下→elder_house） | ⚠️ 需核对新边界位置（3 出口） |
| 场景内硬编码坐标 | town 专属逻辑（`mapKey==='town'` 分支：商店/需求板/猫/镇长家/装饰） | ⚠️ 逐个核对坐标（MapScene.ts 各 `town` 分支） |
| 装饰组 | `setupTownAmbience`/`setupTownDecorations`（MapScene.ts:3106/3194） | ⚠️ 需在新空间重排（装饰零素材，纯代码重排） |

### 验收标准

- ✅ town 从 30×20 扩为 ≥50×35，新增区域为空白空间（无内容堆积）
- ✅ 所有 NPC 站位/出口/交互点坐标在新布局内正确
- ✅ 摄像机边界自动适配，无黑边/出界
- ✅ 现有 Demo 流程（进 town → 商店/NPC/需求板）零回归
- ✅ 新布局为集市广场/老街/河边/空地预留空间（Phase 2 填充）

### 纪律

- **扩容是基础设施，不是内容开发**——禁止借扩地图之名无限造内容。
- 不新增系统 / 不新增大量建筑 / 不动 farm/forest/mine 等其它地图。

## P0-1：章节状态系统

### 目标
支持 Chapter 0 → Chapter 1 状态切换。

### 技术方案（校准后）

```ts
// SaveData.story 新增可选字段（SaveSystem.ts:95-98）
story: {
  storyStep: StoryStep;
  ch1TownIntroDone?: boolean;
  chapter?: 0 | 1;          // 新增：默认 0；第0章终点（observatory_complete）后置 1
}
```

- **写入时机**：仅当 `storyStep === 'observatory_complete'` 时 chapter 置 1（D-025：观星夜是唯一合法章节切换点）。
- **读取接口**：`getChapter(): 0 | 1`（StorySystem 或 SaveSystem，按现有模块归属）。
- **不递增 SAVE_VERSION**：`chapter` 为可选字段，旧档无 → 默认 0，向后兼容（对齐 FEATURE-039 lockedItems 先例）。
- **注意 D-021**：代码/探针中的"Chapter 1"命名迁移暂缓；本字段命名 `chapter` 与叙事层"第0章/第1章"并行不冲突（数值 0/1 = 章节序号）。

### 使用场景
控制 NPC 对白 / 新事件解锁 / 场景变化（第一章专属内容统一 `chapter >= 1` 守卫）。

### 验收标准
- ✅ 新存档默认 Chapter 0
- ✅ Demo 结束（observatory_complete）后进入 Chapter 1
- ✅ Chapter 状态正常保存/读档
- ✅ 老存档兼容（无 chapter 字段 → 0，不触发第一章事件）

## P0-2：条件事件（第一章事件解锁）

### 需求
第一章剧情事件按"章节 + 前置事件完成"条件解锁，如夏雅旧物事件需「老屋整理完成 + chapter=1」。

### 技术方案（二选一，**推荐 A**）

**方案 A（推荐）：组合式条件，零接口改动**
```ts
// 调用处组合判断，不动 EventManager
if (getChapter() >= 1 && hasTriggered('ch1_house_tidy_done') && !hasTriggered('xiya_memory')) {
  triggerOnce('xiya_memory', () => { runEvent(); save(); });
}
```
- 优点：**不碰 EventManager 接口**（守住 08-09 红线），复用现有 `hasTriggered` + `triggerOnce`，行为完全等价。
- 缺点：条件写在调用处（每处 3 行样板）。

**方案 B（备选）：扩展 triggerOnce 支持 condition 参数**
```ts
triggerOnce('xiya_memory', fn, { chapter: 1, requires: ['ch1_house_tidy_done'] })
```
- 优点：声明式，条件集中。
- 缺点：**扩 EventManager 接口**——需制作人批准（08-09 曾定"不再扩接口"，T2 红线可能已随收口解除，需确认）。

### 验收标准
- ✅ 一次性事件（triggerOnce 语义不变）
- ✅ 条件事件（章节/前置事件）
- ✅ 存档恢复后状态保持（gameState 已有此能力）

## P0-3：老屋整理系统

### 目标
第一章开场玩法（章题"归园"核心）：不是家具系统/装修系统，只是"林澈开始生活"。

### 交互点（4 个，house 场景）

| 交互点 | 状态变化 | 叙事 | 实现 |
|---|---|---|---|
| 床 | 未整理 → 完成 | "终于像一个可以生活的地方了。" | house 交互物范式 |
| 灯 | 暗 → 亮 | 晚上房间亮起来 | 交互 + 灯光视觉 |
| 书桌 | 无电脑 → 有电脑 | 过去（左=爷爷旧物）+现在（右=电脑）缩影 | 现有物件拼，零新资产 |
| 收音机 | 触发 MemoryFlashback | "这里曾经有人生活"（生活声音：广播→电流→孩子笑/车铃/风声） | MemoryFlashback + 程序合成音 |

### 技术方案
- 复用 `setupMusicBox`/`setupGrandpaGift` 交互物范式（MapScene house 分支）。
- 每个交互点一次性：`triggerOnce('ch1_bed_done' / 'ch1_lamp_done' / 'ch1_desk_done' / 'ch1_radio_done', ...)`。
- 全部完成 → `triggerOnce('ch1_house_tidy_done')`（作为后续事件前置）。
- 收音机"过去的声音"：程序合成/简短录音（广播站口吻 + 电流 + 生活音），**不做真实电台**（版权+成本+抢戏），内容不讲剧情。

### 验收标准
- ✅ 玩家可进入老屋，触发 4 个交互点
- ✅ 状态保存（triggeredEvents 入档）
- ✅ 再进入仍保持变化（读档恢复）
