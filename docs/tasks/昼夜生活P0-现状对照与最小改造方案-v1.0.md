## 一、核心判断

方案的灵魂是：**借鉴星露谷"有限时间→规划"，不复制"体力惩罚"；让时间决定"世界什么时候发生什么"，让玩家每天做少量有意义的选择。**

先调查后，结论：现有系统已覆盖方案约 **60%** 的 P0 骨架（NPC 日程 / 睡眠推进 / 时段 / 天气），真正需要"新增"的只有 **行动时间成本 + 夜晚疲劳提示**，其余是**衔接/打通**而非新造。

## 三、P0 最小改造方案（只新增/打通，不重构）

### 3.1 新增：行动时间成本（方案 P0 核心缺口）

原则：**"机会成本"而非"惩罚"**——动作消耗游戏内时间，玩家思考"现在做这值不值"；不做体力条/晕倒/丢物/罚钱。

**最小落点**：给 `TimeSystem` 加一个 `consumeMinutes(n)`，并在关键动作成功回调里调用：
- 简单采集 `tryGatherInteract`（已确认位置）→ ~10 分钟
- 对话（`showDialogue`）/ 剧情 → ~0-20 分钟（或剧情按行数）
- 钓鱼一轮成功/失败 → ~20-30 分钟（钓鱼 Phase 1 后接）
- 农田操作/跨区 → 后续接

> ⚠️ **数值先不拍**：需结合当前倍率（现实 1 分 = 游戏 2 小时）实测——若动作消耗时间过多，玩家会"一天只做几件事"，体验反而闷。建议 P0 先做"采集/对话"两个最低风险的，钓鱼/农田留 Phase 后。

### 3.2 新增：夜晚疲劳提示（方案 §十，最小版）

**不做**：丢物/扣钱/晕倒惩罚。
**最小做**：
- 到 ~21:00 起，`tryInteract` 前弹一次提示（`showDialogueText('天色晚了，有些困了……')` 或 HUD 提示），不强制。
- 到 22:00 保持现有"强制停"（已存在）。
- 可选：21:00 后移动速度轻微下降（表现层，不强求）。

### 3.3 打通：时段与现有系统衔接（不新造系统）

- **Discovery 时空调联**：让 `recordDiscovery` 的 `specialDiscoveries` 在 `MapScene` 采集时携带时段/天气条件（如 `rain_forest`/`night_firefly` 已能做），把"青禾镇什么时候有什么"变成玩家学习点。**P1 再做图鉴展示**。
- **NPC 日程 + 时段事件**：现有 `buildSchedule`/`refreshSchedule` 已够；不需要重写。若 P1 要"剧情覆盖日程"，再在 NPC 上加临时覆盖字段。

### 3.4 明确不做（P0 收口）

- ❌ 体力条 / 晕倒 / 丢物 / 金钱惩罚
- ❌ 每个行为都强制消耗时间（只做样本：采集+对话）
- ❌ 每天几十个任务
- ❌ 复杂 NPC AI / 无意义生活系统
- ❌ 大规模重构 TimeSystem/NPC/Discovery

## 四、风险与测试

- **时间倍率**：核心风险。P0 先只在 `tryGatherInteract` 和对话接时间消耗，跑 `probe-gather-flow` 确认不破坏采集；新增 `probe-action-time` 验证动作确实推进时间。
- **存档**：行动时间消耗只改 `TimeSystem` 内存时分，不新增存档字段；`nextDay` 已正确推进。
- **回归**：`probe-nature-p0` / `probe-discovery-record` / `probe-save-nature` / `probe-save-restore` / `probe-gather-flow` / `tsc`。

## 五、施工顺序建议

1. `TimeSystem.consumeMinutes(n)`（最小接口）
2. `tryGatherInteract` + 对话初接（样本：仅 2 处）
3. `probe-action-time`（验证动作推进时间，采集/对话不受破坏）
4. 夜晚疲劳提示（21:00 提示，22:00 保持强制停）
5. 完整回归 + tsc
6. （P1 再做：Discovery 图鉴展示、NPC 剧情覆盖日程、天气参与更多规划）
