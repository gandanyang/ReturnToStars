# 《P0 · 采集深化任务拆分》v1.0

> 状态：📋 任务拆分设计（2026-08-15）｜依据：`自然资源与生活制作系统-v1.0.md` 蓝图 v1.1（P0 范围）
> 定位：P0 只做**采集深化**，为 P1 生活制作铺 data 层；**不改 Gathering 采集动作、不引入制作、不污染现有类**。
> 范围：P0-1 自然状态 / P0-2 条件采集 / P0-3 自然观察（图鉴）/ P0-4 资源标签。

## 一、当前系统摸底

### 1.1 采集（现有，需复用不动）

- `src/data/Gathering.ts`：`GatherKind`（dandelion/wild_berry/wild_mushroom/small_flower/twig）+ `GatherPointDef`（id/kind/x/y/clusterSize）+ 三场景静态分布（TOWN/FOREST/FARM）+ `gatherKindToItem` + `gatherEventKey(scene,id)` + `GATHER_INTERACT_RANGE`。
- `MapScene.ts`：`setupGatherPoints()` / `checkGatherHint()` / `tryGatherInteract()`（triggerOnce 先副效应后标记，item 入 Inventory）→ **只负责"玩家采一下"**。
- 持久化：`triggerOnce('ch1_gather_${scene}_${id}')`，无顶层存档字段。

### 1.2 时间（现有）

- `src/data/TimeSystem.ts`：只有 `day` 和 `hour`（`getTime()`），**无天气、无自然状态**。

### 1.3 物品（现有）

- `Inventory.ts`：采集物 `dandelion/wild_berry/wild_mushroom/small_flower/twig` 已存在（sellPriority=normal）。**无 resource_tags**。

### 1.4 结论

P0 需要一个**独立 `NatureSystem`**（自然状态 + 天气 + 时段 + 特殊资源生成，供采集/未来钓鱼/捕虫复用），`Gathering` 保持"采集动作"职责，`Inventory` 补 `resource_tags`。

## 二、数据结构变化

### 2.1 新增 `NatureState`（自然状态）

```ts
// src/systems/NatureSystem.ts
type NatureStateId = 'germination' | 'thriving' | 'harvest' | 'serene';

interface NatureStateInfo {
  id: NatureStateId;
  label: string;          // 萌芽期 / 繁盛期 / 收获期 / 静谧期
  gatherKinds: GatherKind[]; // 本状态可出现的采集物池
}
```

- 由 `day` 推导（`day -> state`，如 Day1-10 萌芽 / 11-20 繁盛 / 21-30 收获 / 31+ 静谧），**不新增存档字段**（可推导的状态不进入存档，读档幂等）。
- **P0 第一版用固定规则即可**：不做每天随机变化 / 复杂概率 / 多条件组合（否则测试成本爆）；先让世界有"状态"，再让资源响应状态。

### 2.2 新增 `ResourceTag`（★ P0 中比图鉴更重要，是未来所有系统的接口）

```ts
// src/data/Inventory.ts 扩展（P0-4）
type ResourceTag = 'wood' | 'plant' | 'flower' | 'food' | 'insect' | 'mineral' | 'water' | 'special';

interface ItemDef {
  // ...现有字段
  resourceTags?: ResourceTag[]; // P0 只打标签不消费；未来 堆肥=plant+organic / 料理=food / 制作=wood 不再改资源
}
```

- 为现有采集物打标签：dandelion→plant / wild_berry→food / wild_mushroom→food / small_flower→plant+flower / twig→wood。
- **不做百科**：P0 只打标签，不改玩法。

### 2.3 新增 `DiscoveryRecord`（自然观察，P0-3，克制做）

```ts
// src/systems/NatureSystem.ts（持久化：triggerOnce 或用 gameState）
interface DiscoveryCondition { kind: 'weather' | 'phase'; value: string; }

interface DiscoveryRecord {
  id: string;             // 图鉴条目 id，如 'dandelion'
  resourceId: ItemType;   // 关联资源
  firstDiscoverDay: number;       // 第一次采集
  specialDiscoveries: { cond: DiscoveryCondition; day: number }[]; // 特殊条件发现
}
```

- **第一版只记录数据，不加入：描述文本 / 图片 / 分类页 / 成就**（这些属后续图鉴 UI）。
- 足够：蒲公英 普通发现 ✅ / 雨后发现 ✅ / 夜晚发现 未发现。就够。

## 三、NatureSystem 设计

```ts
// src/systems/NatureSystem.ts —— 独立，不污染 Gathering.ts
export class NatureSystem {
  // 职责：当前自然状态 / 天气影响 / 时段影响 / 特殊资源生成 / 自然观察
  getCurrentState(): NatureStateInfo;           // 由 day 推导
  getWeatherToday(ctx): 'rain'|'clear'|'night'|...; // 轻量（可先由 day/随机种子+存档?）
  shouldSpawnSpecial(kind, scene): boolean;     // 条件采集判定
  // 自然观察
  getDiscoveryFor(item): DiscoveryDef | null;
  unlockDiscovery(rid): void;                   // triggerOnce 持久化
  hasDiscovery(rid): boolean;
  getDiscoveredCount(): number;                 // 图鉴进度
}
```

> 天气 / 自然状态由**确定性规则**（day 或内存+存档）推导，避免引入随机天气导致的存档不一致。P0 可用：自然状态=day 映射；天气=凌晨回合随机但入档（若怕复杂，P0 先只做自然状态 + 时段，天气留 P1 或"雨天由环境/任务触发"）。
> 原则上：**P0-1/P0-3 必做；P0-2 条件采集里"时段（夜晚萤火虫/植物）"先做，"天气"视复杂度决定先 on/behind。**

## 四、资源条件生成规则

| 规则 | 触发 | 例子 |
|---|---|---|
| 自然状态过滤 | 采集物池按当前 `NatureState.gatherKinds` 过滤 | 繁盛期才有浆果/荷花 |
| 时段条件 | 特定 `hour` 才可采 | 夜晚萤火虫 / 夜花（`hour>=20 || hour<6`） |
| 天气条件 | 雨后 / 雨天 → 特定资源增加 | 雨后蘑菇增多、河边贝壳 |
| 区域条件 | 特定场景才有 | 森林特殊植物 |

- 生成由 `NatureSystem` 持有，`Gathering` 只按"当前节点是否可采/在场"展示，`tryGatherInteract` 逻辑不变（仍入 Inventory + triggerOnce）。

## 五、图鉴结构（自然观察 · P0-3）

```
自然观察册
├── 常见野花
│    蒲公英    ├ 记录「青禾镇常见野花」
│              └ 特殊「雨后的清晨，花瓣上的露珠会反射星光。」(条件：雨后)
│    小野花    ...
├── 果/菌
│    野莓 / 野蘑菇
└── 木/枝
     小树枝     ...
```

- 解锁：第一次采集（发现记录）→ 图鉴加一；触发特殊条件→补充特殊记录。
- 奖励（不是属性）：NPC 对话多一句、图鉴文字、小事件（花园装饰/解锁等，P1 关联）。

## 六、存档兼容方案

- **不变更现有存档**：`getTime()` 靠 day 推导自然状态 → 读档幂等。
- **自然状态/天气/时段**：由 day 推导，**不进入存档**（读档幂等）。
- **自然观察发现记录 = 玩家记忆，进存档**：新增顶层可选字段 `natureDiscovery`（`SaveSystem`, 对齐 `album` 范式；旧档无此字段 → 空，可正常采集）。只存"真正产生过的发现"（resourceId / firstDiscoverDay / firstDiscoverLocation / specialDiscoveries），**不存图鉴百分比/发现数量**（世界状态推导）。
- 若 P0-2 需要天气：天气状态用**确定性种子（day+固定 salt）**——不引入随机存档漂移。
- `probe-save-nature`：旧档 day=5 加载 → 自然状态推导一致；发现记录序列化/恢复一致。
