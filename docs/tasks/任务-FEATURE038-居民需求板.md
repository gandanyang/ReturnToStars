## 一、目标

林澈用"连接信息"的能力把分散的人与资源连起来：需求板显示村民需要什么，玩家交付后岛屿生活感增强。

## 二、实施内容

### 1. 需求数据

新增模块（建议 `src/systems/ResidentRequestSystem.ts`，模块级单例）：

```ts
interface ResidentRequest {
  id: string;
  npcId: string;
  npcName: string;
  item: string;       // 物品 ID（wood / 食物等）
  itemName: string;
  count: number;
  done: boolean;
  rewardDialogue: string; // 交付后 NPC 反馈（文案制作人定稿，不扩写）
}
```

示例（数值施工时平衡）：

| NPC | 需求 | 数量 |
|---|---|---|
| 小梅（花匠） | 木材 | ×10 |
| 老张（矿工） | 食物 | ×5 |

### 2. 需求板 UI

- 入口：村庄或农场的"信息板"交互物（或轻量 UI 面板）
- 显示：NPC 名字 + 需求 + 数量；已完成打勾
- 复用现有交互/面板模式，不新建重型 UI 系统

### 3. 交付交互

- 找对应 NPC 交付（或需求板一键交付，施工时按体验定）
- 背包有资源 → 扣除 → 标记 done → NPC 反馈对白 → 触发归星记录事件标签 `help_resident`
- 资源不足 → 提示缺什么

### 4. 存档

- 需求完成状态持久化（可选字段兼容旧档，参照 `farm.restore` 模式，版本号不递增）

## 三、不做（红线）

## 七、升级 v1.0（2026-08 制作人拍板）

> 方向确认：居民需求系统作为「资源 → 生活」连接层成立，与采集/钓鱼/种植形成统一范式。
> 定位：`玩家获得资源 → 找到需要它的人 → 小镇产生变化`。

### 实施

1. **物品类别扩展**：`wood / food` → `wood / stone / lantern / food / fish / gather`（鱼/采集物聚合池）。
2. **新增 4 条需求**（结合 NPC 人设 + 世界观「复苏」意象）：

| NPC | 需求 | 数量 | 意象 |
|---|---|---|---|
| 镇长 | 灯笼 | 2 | 老宅归属·「灯亮=有人住」（与灯塔线呼应：让远方知道这里还有人在生活） |
| 阿风 | 食物 | 3 | 童年记忆·河边煮锅（熟人感，非诗意） |
| 老周 | 木材 | 8 | 手艺传承·「旧东西啊，就得有人愿意慢慢修」 |
| 老姜 | 鱼 | 2 | 河边生活·「河里的鱼啊，配点酒，坐河边慢慢吃」 |

3. **世界变化**（交付后场景渲染，幂等，读档恢复）：小梅花架 (farm 5,7) / 老周门框 (farm 11,21) / 镇长灯笼 (town 23,8) / 阿风小灶 (town 6,16) / 老姜鱼篓 (town 6,12)。
4. **多句反馈**：`rewardDialogue` 支持 `\n` 分隔多句，`onResidentDeliver` 逐句播放。
5. 石头类需求支持金币一键补齐。

### 台词定稿（制作人 2026-08 拍板，压说明感，让 NPC 像人）

- 镇长：「码头那盏灯，黑了好些年了。/ 挂上它吧。/ 以后夜里回来的人，也能远远看见这里还有灯亮着。」
- 阿风：「还是热乎的好。/ 小时候咱们在河边煮东西，糊了好几次。/ 你还记得不？」
- 老周：「好料子。/ 门框窗框都能修。/ 旧东西啊，就得有人愿意慢慢修。」
- 老姜：「河里的鱼啊，配点酒，坐河边慢慢吃。」

### 后续方向（制作人建议，不无限增加需求）

居民需求分三类，避免全部塞进面板：
1. **一次性复兴需求**（灯笼/门框/花架）→ 完成后永久存在
2. **生活交换**（食物/鱼/野花）→ 偏关系反馈
3. **活动准备需求**（丰收节/艺术展）→ 走 EventPlan
