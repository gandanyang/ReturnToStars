## 一、事故经过

### 背景

- opencode 完成「资源快速置换 + 小梅 MiniMax 配音」，提交 `9f918f2`（19 files, +213/-4）
- 提交后继续修复「自动售货机与需求板交互重叠」bug（E 键处理顺序问题）

### 发现（提交售货机修复时）

- `git log` 顶部没有 `9f918f2`，`git cat-file -t 9f918f2` 报 `Not a valid object name`
- `git fsck --full` 报 **560 个 missing 对象** + 大量 `invalid reflog entry`
- HEAD 主链（`1ccb64f`）可完整回溯到恢复基线 `556230b`（89 层，即 `disaster-recovery-20260806`）
- 我的全部改动（Economy/FarmRestore/MapScene/ResidentBoardPanel/voicebank/gen_mainline_voice + 音频）都散在工作区/暂存区，**内容零丢失**

### 事故还原

```
opencode 提交 9f918f2（19 文件全入库）
  ↓
其他 Agent 执行 git reset（退回 9f918f2 之前的提交点）
  ↓
9f918f2 的改动退回工作区/暂存区（内容仍在，提交记录被移除）
  ↓
9f918f2 提交对象随后丢失（对象库损坏 / gc / reflog 链断裂）
  ↓
HEAD 链变为其他 Agent 的提交线，9f918f2 从历史消失
```

**根因不是单一误操作，而是没有权限边界**：Agent 不知「这个提交属于谁」，执行整理类操作（reset）时把他人刚提交的成果一并回退。这与 08-06 事故同构（并发操作 + 对象库弱健康），是**第二次**出现。

## 三、根因分析

1. **无权限边界**：Agent 可自由执行 `reset`/`checkout`/`clean`/`rebase`，不知道工作区里有哪些他人的未提交成果
2. **并发无协调**：多个 Agent 并行开发，提交权归属不明确
3. **对象库弱健康**：560 missing 对象说明历史遗留损坏，并发写操作使其恶化

---

## 四、措施（制作人拍板，2026-08-11）

### Git 协作规则 v2（已写入 AGENTS.md）

1. **禁止 Agent 执行**（除非制作人明确批准）：
   `git reset` / `git clean` / `git checkout .` / `git restore .` / `git rebase`
2. **Agent 提交后发现问题禁止回退**：一律用 `git revert`（可追踪），不 reset
3. **不允许多个 Agent 同时操作 main**
4. **重要阶段打 tag**：本次已打 `v0.6-pre-video`（录视频基准）
